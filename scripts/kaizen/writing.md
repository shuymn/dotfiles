# Writing agent knowledge

Rules for editing hiden, `toolchain`, `public-text`, `wasure` and `steward` (source under `home/dot_claude/**`), and for reviewing their diffs.

- Wording: the model reads words literally. A named product or repo ("only on X") reads as "only there", and a blurred name carries nothing; write the mechanism that decides the rule, or delete the line. Mark parentheses that look like closed lists with 「例:」. Keep a Why only where it tells the reader where the rule stops applying (the cases it does not cover, or why another approach is not chosen); never write the history (who corrected it, where something happened). Write each change as the current conclusion and give anything temporary a removal condition. A session editing the live files rewrites only its own lines, so another session's unsynced edit is not lost; a change made on a clean copy of the source may improve any existing line. Apply this to every diff `wasure` reviews.
- Place: a rule that holds for one repository goes in that repository (its docs, memory or `.claude/settings.json`), not in these global files. They are published from a public repository, so their text follows `public-text`.
- Splits: workers reach a skill by name and never open hiden paths. A rule a worker must find alone becomes its own skill with a distinct leading word; what the orchestrator copies into a brief stays a hiden reference.
- Prune pass (when `wasure` shows hiden has grown, or after a large rewrite): list product-named lines, incident-only Whys and no-ops; probe each "ambiguous" claim with 3 blind readers and rotated options, and edit only what they misread, because most flags read fine; have Codex review the diff for lost judgment; then re-sync.
