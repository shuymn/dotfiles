# wasure

このリポジトリの auto memory と、hiden の未承認の書き換えを見直す。完了条件: memory の全項目が行の単位で正本と突き合わされて分類がつき、オーナーが採った分まで適用され、採った docs の変更がマージされ、台帳に 1 行残っている。

## 1. 準備

- 全体の見直し（`~/.claude` の指示と hiden の全文。どのリポジトリでも同じ対象）が要るかを、共有の台帳 `~/.claude/review-ledgers/global.md` の最新の行で決める。行が無い、行のモデル ID がメインのセッションと違う、行の dotfiles のコミットが今の HEAD の祖先でない（`git -C "$(chezmoi source-path)" merge-base --is-ancestor <commit> HEAD` が失敗する）、または `git -C "$(chezmoi source-path)" log --oneline <commit>..HEAD -- dot_claude .chezmoitemplates/agents` に出るコミットがあれば要る。リポジトリごとに走らせると同じ監査が重なるので、要らなければ全体の見直しは飛ばす。要るときも、別のリポジトリのセッションが全体の見直しを進めていれば（`ListAgents` と recall で確かめる）そちらに任せ、このセッションはリポジトリの分だけを行う。
- 全体の見直しが要るときだけ、オーナーに、このセッションで先に `/doctor prompt-audit` を走らせたかを確かめる。まだなら走らせてもらい、その結果も対象に含める。要らないときは走らせない（このリポジトリの指示は 3 と 4 で見る）。
- このリポジトリの auto memory のディレクトリ（システムプロンプトが示す場所）が git リポジトリでなければ、そこで `git init` して現状を最初のコミットにする。remote は付けない。

## 2. 集める

- **memory:** 前回のコミット以降の差分（`git -C <memory dir> diff` と未追跡のファイル）と、索引 `MEMORY.md` を含む全ファイル。初回は全ファイル。
- **hiden の未承認の書き換え:** `diff -ru "$(chezmoi source-path ~/.claude/skills/hiden)" ~/.claude/skills/hiden`。左が承認済み、右がセッションが書き換えた現物。
- **常時読み込む指示:** そのリポジトリの AGENTS.md・CLAUDE.md と、全体の見直しが要るときは `~/.claude/CLAUDE.md`。重複の確かめには、見直しの有無によらず `~/.claude/CLAUDE.md` も正本として読む。
- **正本:** hiden のソース一式（SKILL.md と references）と、そのリポジトリの docs。

## 3. 確かめる

memory はヒントとして扱う。1 ファイルを 1 項目とせず、ファイルの中の規則や事実を 1 つずつ（箇条書きの 1 行、本文の 1 文）次の 4 つで確かめる。同じファイルの中で分類が分かれてよい。

- **正本との重複:** その行が hiden・docs・常時読み込む指示のどこに当たるかを決め、そのファイルを判定のときに開き直して読む（前に読んだ版や記憶で判断しない）。同じ意味の文を `file:line` で引用できれば重複、できなければ重複ではない。言葉の検索は候補を探すのに使い、一致しないことを重複でない証拠にしない。言い回しが違っても、役割の説明や Why が正本と同じなら重複に当たる。
- **hiden とのずれ:** hiden と違うやり方を述べる行と、hiden の各差分では、どちらに揃えれば成果が上がるかを決める。根拠は、それぞれのやり方で実際に起きた結果（台帳、PR、レビューの指摘、やり直し）で示す。リポジトリのやり方が勝てば hiden の該当する文をそれで置き換え、hiden が勝てばリポジトリ側を hiden に揃え、そのリポジトリの事情でしか成り立たなければリポジトリ側に置く。差分があることは、hiden を変える理由にならない。
- **古い・矛盾:** 現物（コード、git、gh、設定）と照らし合わせる。
- **オーナーの意図より硬い:** 規則（feedback と、方針を含む project）ごとに、Why が防ぐ失敗を名指ししているか、恒久なのか見直す条件つきなのかが書かれているかを見る。どちらかが欠けていれば「書き直す」に分け、意図をオーナーに尋ねる。現物からは意図が分からないので、推測で埋めない。

## 4. 分類して表で提案する

各行を次のどれかに分ける。

| 分類 | 行き先 |
|---|---|
| 残す | そのまま（リポジトリの非公開の知識、未確定の気づき） |
| 統合 | 同じ場面で読む memory 同士を 1 ファイルにまとめる。中身が重複していなくても、読む場面が同じなら対象 |
| 昇格 | hiden とのずれで、一般化でき hiden より成果が上がると決めた手法。`~/.claude/skills/hiden/` の該当する文を置き換えて移し、memory から消す。置き換える文が無く行を足すときは、hiden の既存のどの文でも防げない失敗を名指しする。hiden に同じ意味の文があれば昇格ではなく削除 |
| docs へ | そのリポジトリで作業する誰にでも要る規則。リポジトリの docs への変更として提案する |
| 書き直す | 日記の形（日付つきの追記、経過）を、現時点の結論に書き直す |
| 削除 | 正本にある（引用した `file:line` を添える）、hiden に揃えると決めた、古い、コードや git から分かる、状態（正本は issue と作業ごとの引き継ぎ）、撤去の条件を過ぎた |
| hiden: 承認 / 戻す | セッションが書き換えた hiden の各差分。hiden とのずれで、差分が勝つと決めたものだけ承認し、行を足す差分には昇格と同じ名指しを求める |

行を消して残りが少なくなったファイルは、残った行だけで読めるように書き直す。正本を指す一文（「hiden の orchestration.md の進め方で行う」など）で足りる部分は、その一文に置き換える。

常時読み込む指示とその索引の各行には、「その行が防ぐ失敗を名指しできるか、そのモデルが言われなくてもそう振る舞うのではないか」を当て、名指しできない行を削除の候補にする。全体の見直しが要るときは、同じ問いを hiden の各文にも当てる。そこで出た削除の候補は表に載せ、採ったものは chezmoi のソースから消す。効くかどうかで判断が割れる行や hiden の差分は、議論で決めずに、新しいサブエージェントで比べる。その行が効くはずの場面を複数用意し、場面ごとに行の有無の両方を走らせる。進め方の行は、差が出なければ削除の候補にする。権限、破壊的な操作、外部への書き込み、公開テキストの行は、まれな事故が少ない試行には現れないので、実際の事故を Why に持つなら差が出なくても残す。

表は、判断の要るもの（統合、昇格、docs へ、削除、hiden の差分、常時読み込む指示の削除候補）だけをオーナーに見せる。各行に推奨（採る / 採らない）と根拠を付け、「書き直す」で意図を尋ねる問いにも答えの案と推奨を添える。「残す」と単純な「書き直す」は件数だけを伝える。

## 5. 適用する

- 採否は `AskUserQuestion` で 1 回だけ尋ねる。選択肢は「推奨どおり（Recommended）」と「行を指定して変える」で、後者では名指しされた行だけを変え、残りは推奨どおりに採る。問いには、採った docs の変更をコミット・PR・CI・マージまで進めることを書く。この返事が、表の各行とマージまでの許可になる。
- 承認の後は、採った分を最後まで進める。止まるのは表に無い判断が新しく出たときだけで、そのときも推奨を付けて同じ形で尋ねる。
- **memory:** 確認を終えたら、編集が無くてもその時点の内容を `git -C <memory dir>` でコミットする（コミットが「確認済み」の印）。メッセージは「wasure: 」に続けて要約。
- **hiden の昇格:** 足す文に、足す前に 3 の「正本との重複」を hiden に対してもう一度当て、現物の `~/.claude/skills/hiden/` に書く。ソースとの差分として残り、次の wasure の「hiden: 承認 / 戻す」で審査される。
- **hiden の差分:** chezmoi のソース（`chezmoi source-path ~/.claude/skills/hiden`）を直接直す。承認した差分はソースに Edit で写し、新しいファイルはソースにコピーし、消されたファイルはソースからも消す。却下した差分は現物を Edit で元に戻す。保留した差分は現物に残す。
- **docs へ・常時読み込む指示:** そのリポジトリにあるものは、ブランチで編集し、hiden の commit-pr.md の手順でマージまで進める。正本が別のリポジトリにあるもの（`~/.claude/CLAUDE.md` など）は、変更案をオーナーに渡す。

## 6. 記録する

`~/.claude/review-ledgers/<repo>.md` に 1 行追記する: 日付、`wasure`、メインのセッションのモデル ID、各分類の件数、hiden の行数の増減、目立った腐り方（例: 同じ規則が硬く書かれていた）。

全体の見直しをしたときは、`~/.claude/review-ledgers/global.md` にも 1 行追記する: 日付、`wasure`、モデル ID、見直しを終えた時点の `git -C "$(chezmoi source-path)" rev-parse --short HEAD`、見直したリポジトリ、全体の分の件数。記録するのは、採った変更が dotfiles の HEAD に入り、`chezmoi diff ~/.claude/CLAUDE.md` が空になってから（見直した現物と記録するコミットを揃える）。コミットや適用を待つ間は記録しない。適用で、採った変更のほかにも見直した時点から本文が変わっていれば、その差分を見直してから記録する。採った変更より前のハッシュを書くと次の回が自分の変更を見てまた全体の見直しを要ると判定し、適用前の現物を見直してコミットだけを書くと新しい版の見直しを飛ばす。
