# wasure

このリポジトリの auto memory と、hiden の未承認の書き換えを見直す。完了条件: 対象の全項目に分類がつき、オーナーが判断した分まで適用され、台帳に 1 行残っている。

## 1. 準備

- オーナーに、このセッションで先に `/doctor prompt-audit` を走らせたかを確かめる。まだなら走らせてもらい、その結果も対象に含める。
- このリポジトリの auto memory のディレクトリ（システムプロンプトが示す場所）が git リポジトリでなければ、そこで `git init` して現状を最初のコミットにする。remote は付けない。

## 2. 集める

- **memory:** 前回のコミット以降の差分（`git -C <memory dir> diff` と未追跡のファイル）と、索引 `MEMORY.md` を含む全ファイル。初回は全ファイル。
- **hiden の未承認の書き換え:** `diff -ru "$(chezmoi source-path ~/.claude/skills/hiden)" ~/.claude/skills/hiden`。左が承認済み、右がセッションが書き換えた現物。
- **常時読み込む指示:** `~/.claude/CLAUDE.md` と、そのリポジトリの AGENTS.md・CLAUDE.md。
- 移行中の `~/.claude/memory/` が残っていれば、それも対象に含める（撤去の条件: hiden への移行を終えてディレクトリを消したら、この行を消す）。

## 3. 確かめる

memory はヒントとして扱い、1 項目ずつ現物（コード、git、gh、設定）と照らし合わせる。古い、矛盾している、オーナーの意図より硬い、の 3 点を見る。

## 4. 分類して表で提案する

各項目を次のどれかに分ける。

| 分類 | 行き先 |
|---|---|
| 残す | そのまま（リポジトリの非公開の知識、未確定の気づき） |
| 統合 | 重複をまとめた 1 ファイル |
| 昇格 | 一般化できる手法は `~/.claude/skills/hiden/` へ移し、memory から消す |
| docs へ | そのリポジトリで作業する誰にでも要る規則。リポジトリの docs への変更として提案する |
| 書き直す | 日記の形（日付つきの追記、経過）を、現時点の結論に書き直す |
| 削除 | 古い、コードや git から分かる、状態（正本は issue と作業ごとの引き継ぎ）、撤去の条件を過ぎた |
| hiden: 承認 / 戻す | セッションが書き換えた hiden の各差分 |

常時読み込む指示とその索引の各行には、「その行が防ぐ失敗を名指しできるか、そのモデルが言われなくてもそう振る舞うのではないか」を当て、名指しできない行を削除の候補にする。

表は、判断の要るもの（統合、昇格、docs へ、削除、hiden の差分、常時読み込む指示の削除候補）だけをオーナーに見せる。「残す」と単純な「書き直す」は件数だけを伝える。

## 5. 適用する

- オーナーが採った分だけを適用する。
- **memory:** 確認を終えたら、編集が無くてもその時点の内容を `git -C <memory dir>` でコミットする（コミットが「確認済み」の印）。メッセージは「wasure: 」に続けて要約。
- **hiden:** chezmoi のソース（`chezmoi source-path ~/.claude/skills/hiden`）を直接直す。承認した差分はソースに Edit で写し、新しいファイルはソースにコピーし、消されたファイルはソースからも消す。却下した差分は現物を Edit で元に戻す。保留した差分は現物に残す。
- **docs へ・常時読み込む指示:** 変更案をオーナーに渡す。

## 6. 記録する

`~/.claude/review-ledgers/<repo>.md` に 1 行追記する: 日付、`wasure`、各分類の件数、目立った腐り方（例: 同じ規則が硬く書かれていた）。
