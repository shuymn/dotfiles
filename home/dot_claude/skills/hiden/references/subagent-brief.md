# worker への指示書

指示書は英語で、先頭に固定の 1 行（`Follow the body of ~/.claude/agents/opus-worker.md.`）、その作業が当たるルールブロック（下の節を英語にして本文で貼る）、作業内容の順に書く。worker の常時の項目は `opus-worker.md` にあるので写さず、キットの worker の項目（[attention.md](attention.md)）はルールブロックと同じく本文で貼る。ルールブロックは参照でなく本文で渡す（本文に無い規則は守られない）。

## コミットする作業のルールブロック

- フックの失敗は直すか、未コミットのまま報告する。`-n`、`core.hooksPath`、環境変数でも回避しない。
- 作業の退避は WIP コミットか `git show` での複製で行う（stash は worktree 間で共有される）。復元は自分が変えたファイルだけを、自分のバックアップか `git show HEAD:<path> > <path>` から行う。
- [commit-pr.md](commit-pr.md) で決めた言語を書き、`commit` スキルにその言語のフラグを付けてコミットするか、未コミットのまま返させる。公開リポジトリで書くコミット、変更履歴、文書、コメントは `public-text` スキルに従う。
- テストや golden に書くパスは、ホームディレクトリの形（例: `/Users/…`、`/home/…`、`C:\Users\…`）を避け、`/work/…` のような中立のパスにする（公開の検査がコミットごとに止め、直すには履歴の組み直しが要る）。
- push・PR・merge・gh の書き込みはオーケストレーターに任せる。

## 環境に触れる作業のルールブロック

- 止めるのは自分が起動したものだけを PID で（ポートや名前で引いた kill は他のセッションを止める）。
- 一時ファイルは worktree の中に置き、最終報告の前に消す。テストのフィクスチャは OS の一時ディレクトリで、`TMPDIR` は worktree の中にしない（フィクスチャが別のリポジトリの中に置かれる）。
- デプロイ、ストレージ、シークレット、パッケージ公開の書き込みは、スクリプトや CLI 経由でもオーケストレーターに任せ、dry-run も行わない。dry-run のフラグは `--help` か偽のバイナリで確かめる（例: `pnpm run x -- --dry-run` は `--` がそのまま渡り、フラグが効かず実行される）。手順書に書いた書き込みのコマンド（登録・更新・削除）は、実行せず読んで確かめる。

## リソースのライフサイクルを足す作業のルールブロック

作業が子プロセス、socket、要求、cache、待ちを足すときだけ貼る。期限の無い待ちに期限を付け（既存の期限が掛かっていればそれでよい）、すべての終了パス（例: 起動・接続の失敗、期限切れ、取消し、親の終了、シグナル、起動の途中の失敗）で後始末し、結果を採用する時点でそのリソースや要求がまだ有効かを同種の結果を採用する既存パスと同じ有効性チェックで確かめ、破棄するときはそのリソースを利用可能と示している状態を解除する。失敗パスごとにテストを書く。削除や上書き（例: ディレクトリ、worktree、ref、設定）は、自分が作ったと記録と実体の両方で確かめられたものだけにし、symlink はたどらない。

## 指示書に書く報告の仕様

[judgment.md](judgment.md) の「信頼できる既存の実装と設計を先に調べる」「リポジトリ全体の一貫性」。変更の安全を支える事実とその証拠レベル。修正を戻して落とした回帰テスト（[verification.md](verification.md) の「証拠の強さ」）。指示書が挙げた証明に限らず、設計の主張ごとに守るテストと、それを落とす具体的な変更（変異）の表。確かめ・測定の対象 commit と方法。

## 報告の確認

報告を受けたら、完了条件の出力（テスト件数を含む）、規則違反、コミットの件名、設計からの逸脱とその理由、`git status` がクリーンかを確かめ、飛ばされた検査はやり直す。証拠が「言っただけ」の主張は、走らせ直すか未証明として扱う。
