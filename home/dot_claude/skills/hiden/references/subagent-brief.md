# 実装エージェントへの指示書

指示書の先頭の制約欄に、次の規則を毎回同じ文面で本文として書く（先頭が同じならプロンプトキャッシュが効く）。CLAUDE.md への参照だけでは守られず、他のセッションのテストの停止や、オーナーのアカウントへの実際のデプロイが起きた。

- **フックの失敗:** 直すか、未コミットのまま報告する。フックは必ず通す（メッセージだけの amend や merge commit でも）。
- **作業の退避と復元:** 退避は WIP コミットか `git show` での複製で行う（stash はワークツリー間で共有される）。復元は自分が変えたファイルだけを、自分の控えか `git show HEAD:<path> > <path>` から行う。
- **プロセスを止めるとき:** 自分が起動したものだけを PID で止める。
- **一時ファイル:** ワークツリーの中に置き（`TMPDIR` もワークツリー内に設定）、最終報告の前に消す。
- **外部への書き込み:** push、PR、merge、外部サービスへの書き込み（デプロイ、ストレージ、シークレット、パッケージの公開、gh の書き込み）はメインのセッションに任せ、dry-run も行わない。dry-run のフラグは `--help` か偽のバイナリで確かめる。`pnpm run x -- --dry-run` の `--` がそのまま渡って、本当にデプロイされたことがある。
- **コミット:** [commit-pr.md](commit-pr.md) で決めた言語を指示書に書き、帰属表示の行を付けさせない。`commit` スキルにその言語のフラグを付けてコミットするか、未コミットのまま返させる。
- **公開テキスト:** コミット、変更履歴、文書、コメントは [judgment.md](judgment.md) の「公開テキスト」に従う。
- **新しい資源の経路:** 子プロセス、socket、要求、cache の項目を足すたびに、期限の無い待ちに期限を付け（既存の期限が掛かっていればそれでよい）、すべての終わり方（起動・接続の失敗、期限切れ、取消し、親の終了）で後始末し、結果を採用する時点でその資源や要求がまだ有効かを既存の経路と同じ検査で確かめ、破棄するときはその資源を利用可能と示している状態を解除する。失敗の経路ごとにテストを書く。Why: 経路を足すたびに、同じ種類のレビュー指摘が繰り返し出た。
- **報告させること:** [judgment.md](judgment.md) の「ライブラリを先に検討する」「リポジトリ全体の一貫性」の判断。変更の安全を支える事実とその証拠の段。回帰テストを、修正を戻して落としたこと（[verification.md](verification.md) の「証拠の強さ」）。確かめ・測定の対象 commit と方法。

報告を受けたら、完了条件の出力（テスト件数を含む）、規則違反、コミットの件名、設計からの逸脱とその理由を確かめ、飛ばされた検査はやり直す（例: `origin/main..HEAD` に対する秘密情報の検査）。証拠が「言っただけ」の主張は、走らせ直すか未証明として扱う。
