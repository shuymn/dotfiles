# デバッグ

直す前に、どこで壊れているかを証拠で決める。

- **再現:** 確実に起こせる手順を作る。起こせないなら、推測せずに観測を足す。
- **境界で観測:** 複数の部品（CI → ビルド → 署名、API → サービス → DB）を通るなら、各境界で入る値と出る値、設定や環境が届いているかを一度に記録し、壊れる層を決めてからその層を調べる。
- **出どころまで遡る:** 悪い値を、呼び出し元をたどって作られた場所まで遡り、症状の場所ではなくそこを直す。
- **動く例との差:** 同じリポジトリの似た動くコードと比べ、違いを小さなものまで全部挙げる。
- **テスト間の汚染:** 単独では通り一式では落ちるなら、先に走るテストを二分探索で絞る。
- **仮説は 1 つずつ:** 「X が原因、なぜなら Y」と書き、一度に 1 つだけ変えて確かめる。
- **修正が 2 回外れたら:** 3 回目の前に、外れた修正が共通して前提にしていた 1 文を書き出し、それが偽なら結果が変わる観測で直接確かめる。崩れたら原因は別の所にある。成り立つなら次の「なぜ」を問う。
- **直したら:** 修正を戻して落ちる回帰テストを残す（[verification.md](verification.md) の「証拠の強さ」）。

Why: 外れた修正はそれぞれ、その前提に反する証拠である。同じ前提のまま 3 回目を足すと、原因が無いと証拠が示している所に労力を使う。
