# キット・委任・引き継ぎ

## キット

委任の前にキットを作り、本質と現在の状態を `state.md` に置く。

- `stack kit open <名前>` でキットを作るか開き、このセッションに結び付ける（外すのは `stack kit close <名前>`）。引き継いだセッションも開き直す。
- `state.md`（`NORTH.md` でもよい）: 先頭に本質（目的、完了条件、クリティカルパス、オーナーの指示と決定、制約）、続けて進行中、次の一手、未決を書く。後の判断が依存する現在の状態だけを置き、委任・完了・マージ・オーナーの決定のたびに更新する。
- `attention/items.json`: キット固有で毎回守るべき規則（フックや lint で強制していないもの）を `{"items":[{"role":"orchestrator"|"worker"|"all","rule":"…"}]}` で書く。キットを作るときと開いたときに、`role` が `orchestrator` で次の `rule` の項目が無ければ先頭に足す: `compaction の後は、進行中のステップの hiden reference を読み直してから続ける`。`worker` 向けの項目は指示書に本文で貼る。
- worker が複数なら、状態を出力する実行可能な `bin/board` を置いてもよい（任意）。
- compaction の後に復元されたキットの内容が要約と食い違えば、キットの内容を正とする。

## 委任と監査（steward）

- 判断は自分でし、作業と監査は、指示書と報告を読む費用に見合うときだけ渡す。
- 監査（steward）は読み取り専用で、依頼文に `Follow the body of ~/.claude/agents/steward.md.` とキットのディレクトリを渡し、フェーズの終わり、状態が古いとき、引き継ぎの前、振り返りで頼む。実行は [review.md](review.md) の「実行」の `agy-run` で行い、`agy-run` が使えないとき（同「担当」の条件）はオーケストレーターと同じモデル・労力で走らせる。`agy-run` の実行が失敗した後は、先に [review.md](review.md) の「実行後の確認」を済ませる。
- `stack pr merge` の後に `audit due (…): run steward on kit <slug>` が出たら、費用の見積もりはせずに必ず、`<slug>` のキットのディレクトリ（`[kit].root/<slug>/`、デフォルト `~/.local/state/stack/kits/<slug>/`）を確かめ、そのディレクトリだけを足した同じ書式で（自分の結論は添えない）steward をバックグラウンドで起動し、待たずに次の作業へ進む。ディレクトリが決まらなければ起動せず、slug を未解決として報告する。
- `agy-run` でバックグラウンド監査を走らせる間は、結果を読むまで同じ作業ツリーで編集しない（次の作業は別 worktree で進めるか読み取りだけにする）。見落としは台帳に記録する。

## 引き継ぎ

非常に長いセッションでは、尋ねずに新しいセッションへ引き継ぐのがオーナーの常設の依頼。環境に手段があるときだけ、`stack kit open` と compaction の後に出る環境ごとの手順で行う。

- 子セッションは起動元のセッションにしか報告できないので、実行中またはフォローアップ予定の子セッションが無いフェーズの終わりで、`state.md` を更新してから、リポジトリのルート（worktree なし）で「`stack kit open <名前>` を実行して続ける」として起動し、立ち上がったのを確かめて止まる。
- 新しいセッションは `<orchestration-state>` が復元されたことを確かめ（無ければ止まる）、PR の待ちを置き直す。
