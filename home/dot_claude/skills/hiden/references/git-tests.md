# git を走らせるテスト

git を呼ぶテスト（例: 手元のリポジトリを相手にする CLI、フック、移行スクリプト）は、テストの速さより仕組みでの安全を優先し、隔離はテストを走らせる側（リポジトリのテスト実行口。Makefile や CI のラッパーなど）が強制して実装エージェントの注意に頼らない。

- **走らせる側で閉じ込める:** テストの実行は、先にビルドを済ませてから OS のサンドボックス（macOS は `sandbox-exec`、Linux は bubblewrap や landlock、なければ使い捨てのコンテナ）の中で行い、書き込みをテスト用の一時ディレクトリだけに許す。本物のリポジトリ・ソースツリー・`$HOME` への書き込みは、どのテストからでも権限エラーで落ちる。テストの起動は `env -i` から作った環境で行う。
- **起動口は名前付きの操作だけ:** テストから子プロセスを起こす口は、環境を作って渡すヘルパー 1 つにし、それ以外の `Command::new` などは lint（clippy の `disallowed-methods` など）で禁止する。git に自由な引数を渡せる口は作らず、init、commit、push などの名前付きの操作だけにする。各操作は自分で argv を組み、テストの値は `--end-of-options` の後に置き、リポジトリはまだ無い名前に作って記録したハンドルで渡し、git を呼ぶ直前に毎回、触るリポジトリの `.git` と git dir がフィクスチャ（どのリポジトリの外にも置く、OS の一時ディレクトリの `mkdtemp`）の中かを確かめ直す。Why: 引数を読んで外への書き込みを止めるガードは、値の書き方（例: `-f/abs`、symlink、外を指す `.git` ファイル）を変えるとすり抜けられる。
- **環境は作って渡す:** 子の git には、`process.env` から削るのではなく許可した変数だけで作った環境を渡す。`HOME`・`XDG_CONFIG_HOME`・`GIT_CONFIG_GLOBAL` はフィクスチャの中を指し、`GIT_CONFIG_NOSYSTEM=1`、`GIT_CEILING_DIRECTORIES` はフィクスチャの親にする。フック（pre-push、lefthook）から走ると継承される `GIT_DIR`・`GIT_INDEX_FILE`・`GIT_WORK_TREE` などが子に届くと、`git -C <fixture>` でも本物のリポジトリに書く。作者は `GIT_AUTHOR_*`/`GIT_COMMITTER_*` の環境変数だけで与え、`git config user.*` や `--global` の設定は書かない。隔離した設定で署名とフックを切る。
- **本物のリポジトリの番人:** テスト一式の前後で、本物のリポジトリの ref の一覧、HEAD、worktree の一覧、設定・フック・index（split index の共有ファイルを含む）のハッシュと、残ったプロセス（fsmonitor のデーモンなど）を比べ、違えば失敗にする。わざと 1 つのコマンドを本物に向けて番人が落ちるのを確かめてから使う。フックと同じ `GIT_*` を export した状態でも一式を一度走らせる。
- **製品側:** 製品のコードが host のリポジトリで git を呼ぶなら、継承したリポジトリの位置の変数（`GIT_DIR` など）を外して `git -C <対象>` で呼ぶ。
